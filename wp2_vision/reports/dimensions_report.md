# WP2 — Dimension module (length, width, depth): data, fine-tuning, out-of-distribution test

## Result

On potholes from a camera, lab and country never used for training (Fan et al. stereo, 79 potholes,
3D ground truth accurate to 2.2 mm), with the camera height and focal length known (the bus-camera case):

| Pipeline | Depth error | Length error | Width error |
|---|---|---|---|
| Before this work (box, 0.2 clamp bug) | 1.6 cm (88 %) | 9.6 cm (134 %) | 12.3 cm (149 %) |
| **Delivered, true outline** | **0.9 cm (40 %)** | **0.9 cm (11 %)** | **0.5 cm (5 %)** |
| **Delivered, fully automatic** (outline drawn by the model, 27/79 found) | 1.2 cm (41 %) | 1.4 cm (12 %) | 1.9 cm (9 %) |

Errors are mean absolute errors; percentages are median relative errors. The test potholes are small
(1–19 cm long, 0.4–4.4 cm deep) and the camera is 0.35–0.48 m from the road. Contract target for depth: ≤ 3 cm.
Without any camera information ("blind" photo) absolute sizes remain unusable (errors of several decimetres):
a single photo cannot give scale.

## What was changed

1. **Calibration bug fixed** (`depth.py`, `scale_factor`): the camera-height correction was clamped to ×0.2–×5.
   A street-scene model is ~8× off when the camera is close to the road, so the clamp blocked the correction.
   Now ×0.02–×20. Alone, this cut length error from 9.6 to 1.0 cm.
2. **Measurement on the outline** (`box_size_m`, `pothole_depth_cm`, `mask=`): defect points are projected on
   the road plane fitted on the intact asphalt around it; length/width = extents along / across the road.
   Validated on the ground-truth point clouds: the method returns the true dimensions exactly.
3. **Depth model fine-tuned on real road-surface depth** (`scripts/train_depth.py`, `models/depth_finetuned`):
   Depth Anything V2 Metric-Outdoor-Small, RSRD dense (Tsinghua; stereo + LiDAR; 2,493 train / 300 test frames),
   scale-invariant log loss, 6 epochs. In-distribution (RSRD test): relative error 135 % → 2.0 %, error on the road
   ahead 5.85 m → 9.6 cm.
4. **Split roles** (`DepthEstimator(relief_model_id=...)`): the fine-tuned model learned the single camera mounting
   of the RSRD vehicle (it predicts the road tilted ~60° whatever the photo), which ruins length/width on another
   camera (11.8 cm). Crop augmentation + frozen encoder (v2) reduced but did not remove it (2.9 cm). The pipeline
   therefore takes the scene geometry (road plane, scale, length, width) from the original model and only the depth
   of the hole from the fine-tuned one.
5. **Pothole outline model** (`scripts/prepare_seg.py`, `scripts/sam_pseudolabel.py`, `scripts/train_seg.py`,
   `models/pothole_seg.pt`): YOLOv8s-seg trained on Pothole Mix (SHREC 2022) + 2,551 outlines generated by SAM 2
   from the pothole boxes of the WP2 detection dataset (train/val only; 228 rejected by a quality filter).
   Pothole Mix hand-drawn validation: mask mAP50 70.8 %, recall 73 %. On the close-up Fan photos it finds
   27/79 potholes (v1 without SAM outlines: 4/79): close-up top-down views remain under-represented.

## Citizen photos (no calibration)

A citizen photo carries no camera height and often loses its focal length. Test: RSRD test split (300 frames,
LiDAR depth, camera ~1.1 m above the road, about a hand-held height), a road patch used as a ruler
(`scripts/eval_citizen_scale.py`, `reports/citizen_scale_rsrd*.md`):

| Information available with the photo | Length error | Width error | Within 20 % |
|---|---|---|---|
| Nothing (depth model's own scale, 70° assumed) | 129 % | 241 % | 0 % |
| EXIF focal, depth model's own scale | 114 % | 133 % | 0 % |
| Depth Pro (Apple 2024, estimates focal + scale), blind | 78 % | 73 % | 2 % |
| EXIF focal + assumed hand-held height 1.40 m | 19 % | 11 % | 51 % |
| **EXIF focal + phone tilt + height (pure geometry)** | **1 %** with the true height | **0 %** | **100 %** |

With the phone tilt, length and width no longer depend on any AI: the road plane follows from tilt + focal +
height and each pixel is placed by ray-plane intersection (`depth.geometric_size_m`, unit-tested in
`tests/test_geometry.py`). The only error left is the height guess, so the citizen app now asks "Photo prise :
debout / accroupi(e)" (1.40 m / 0.75 m): for a standing adult (1.25-1.55 m) that is ≤ 12 % error.
Depth Pro estimates the focal well (13 % median error) but tilts the road plane, so it was not adopted.

What the app sends now (front → backend → WP2 `/v1/detect`): EXIF focal read before the photo is shrunk
(`cameraMeta.ts`), phone tilt from DeviceOrientation (camera captures only), posture. WP2 returns, per
detection, `measure_method` and `size_uncertainty_pct`, shown on the defect record:

| measure_method | when | typical margin |
|---|---|---|
| `citizen_geometry` | camera capture with tilt + EXIF focal | ± 15 % |
| `citizen_estimate` | gallery photo / no tilt | ± 40 % (order of magnitude, displayed rounded) |
| `vehicle_calibrated` | bus camera, known height (and tilt once WP1 calibrates the mount: ± 5 %) | ± 30 % |

## Class detection on citizen photos

Citizen photos are often close-ups, where the detector misses potholes. Test sets: the v2 test split (1,263 images,
same images for every model) and pothole600 (240 close-up photos, never trained on):

| Pothole AP50 | street photos (v2 test) | close-ups (pothole600) |
|---|---|---|
| Detector v2 (kept) | **62.5 %** | 25.3 % |
| Detector v3: + Pothole Mix converted to boxes | 61.6 % (all defects 50.5 vs 52.1 %) | 14.5 % |
| Detector v4: + strong zoom augmentation | 61.5 % (all defects 51.5 %) | 18.2 % |
| **v2 + outline model as a 2nd pothole detector** (its confidence × 0.5, chosen on validation) | 61.7 % | **43.2 %** |

v3 and v4 were rejected: both are worse on both sets. The merge is enabled for citizen and pedestrian photos only
(`VisionPipeline.outline_potholes`), bus frames keep the detector alone. Crack classes are unchanged (v2).

deployment would need models retrained on data with commercial rights (e.g. WP1 captures).

## Caveats

- The geometry/relief split was chosen after looking at the Fan results: Fan is unseen by every model's training,
  but not by that design choice. A second independent test (WP1's 40 tape-measured defects) should confirm it.
- The camera height and focal length must be known (calibrated bus camera). For citizen photos a 1.5 m hand-held
  height is assumed: sizes are indicative only.
- 0.4–4.4 cm deep potholes make relative depth error look large (40 %); absolute error is 0.9 cm.

Reproduce: `python scripts/eval_dims_fan.py --relief models/depth_finetuned --seg models/pothole_seg.pt --seg-conf 0.1`
(per-run tables in `reports/dims_fan_*.md`).
